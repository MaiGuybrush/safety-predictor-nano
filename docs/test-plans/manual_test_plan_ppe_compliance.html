1. 測試目標與範圍說明

本手動測試計畫專門針對 Git Commit 71dbd1347e3fa82e455cba9a251892d5138244af 所引入之完整工安功能進行驗收。涵蓋的核心功能包含：

  • 配置架構與熱載入 (Config Hot-Reload)：支援 ppe_class_mapping、external_states 與 compliance_rules 宣告式矩陣，檔案異動即刻熱生效。
  • 外部設備狀態雙軌同步 (Dual-Track State Sync)：包含背景 HTTP GET 輪詢（支援 JSON 點路徑解析與斷網降級）與 POST /api/external_state Webhook 主動推送。
  • PPE 雙模防護裝備比對演算法：直接負類別判定 (direct_negative) 與頭部錨點寬鬆空間包含比對 (head_anchor)，特別驗證人員彎腰或蹲下作業抗誤報能力。
  • 條件式工安合規引擎 (Compliance Rule Engine)：依外部狀態（如 MAINTENANCE）、區域與物件，驗證 require_any（如三角錐/護欄阻隔）、require_all、require_ppe。
  • Web UI 畫布即時視覺回饋：全螢幕綠框（合規人員/阻隔物）、亮紅框與違規標籤（違規人員）、阻隔物缺失橫幅（Missing Barriers Banner）與警戒區動態 Badge。
  • 事件日誌與快照留存 (EventLog & Snapshot)：違規觸發 EventStart 與 .jpg 快照寫入，違規解除自動拋出 EventEnd。
  • 邊緣硬體實機驗收 (Raspberry Pi 5)：二進位部署、推論幀率（2~5 FPS）與長時運行資源消耗驗證。

2. 測試前置準備與即用型輔助工具

測試執行模式說明： 優先於 PC 開發環境搭配 Mock MES API、PowerShell 指令與本機測試視訊完成邏輯與 UI 驗收；通過後部署至 Raspberry Pi 5 邊緣機執行實機功能與幀率審核。

2.1 快速啟動輕量 Mock MES API 服務 (Python 內建)

外部狀態輪詢功能需要一個 REST API 回應 JSON 格式的設備狀態。於終端機執行以下單行指令即可啟動 Mock API 伺服器（監聽 8081 埠）：

# 建立 mock_mes.py 並啟動在 8081 埠 (PowerShell / CMD 皆適用)
python -c "
import http.server, json
class Handler(http.server.BaseHTTPRequestHandler):
    def do_GET(self):
        self.send_response(200)
        self.send_header('Content-Type', 'application/json')
        self.end_headers()
        response = {'data': {'equipment': {'status': 'MAINTENANCE'}}, 'code': 0}
        self.wfile.write(json.dumps(response).encode('utf-8'))
http.server.HTTPServer(('127.0.0.1', 8081), Handler).serve_forever()
"

2.2 Webhook 狀態推送指令範例 (PowerShell / cURL)

測試人員可透過以下指令，主動模擬 MES / SCADA 發送 Webhook 覆寫機台狀態：

# 方式 A：Windows PowerShell (Invoke-RestMethod)
Invoke-RestMethod -Uri "http://127.0.0.1:8188/api/external_state" -Method Post `
  -ContentType "application/json" `
  -Body '{"source": "stocker_01", "status": "MAINTENANCE", "ttl_seconds": 60}'

# 方式 B：cURL (Linux / macOS / Git Bash)
curl -X POST http://127.0.0.1:8188/api/external_state \
  -H "Content-Type: application/json" \
  -d '{"source": "stocker_01", "status": "MAINTENANCE", "ttl_seconds": 60}'

2.3 驗收專用 config.yaml 完整參考範例

ppe_class_mapping:
  person: "person"
  head: "head"
  helmet: "helmet"
  no_helmet: "no_helmet"
  vest: "vest"
  no_vest: "no_vest"
  cone: "cone"
  guardrail: "guardrail"

external_states:
  stocker_01:
    url: "http://127.0.0.1:8081/api/v1/equipment/status"
    method: "GET"
    interval_seconds: 5
    json_path: "data.equipment.status"
    timeout_seconds: 2
    fallback_value: "UNKNOWN"

compliance_rules:
  - id: "maintenance_barrier_rule"
    name: "機台維護阻隔防護規範"
    enabled: true
    when:
      external_state:
        stocker_01: "MAINTENANCE"
      zone: "維護警戒區"
      detected: ["person"]
    require_any:
      - "cone"
      - "guardrail"
    require_ppe:
      - "helmet"
      - "vest"
    on_violation:
      severity: "HIGH"
      category: "safety_barrier_missing"

streams:
  - url: "rtsp://127.0.0.1:8554/cam1" # 或測試影片本機路徑
    label: "Stocker02"
    zone:
      zone_name: "維護警戒區"
      polygon: [[0.15, 0.20], [0.85, 0.20], [0.85, 0.85], [0.15, 0.85]]
      trigger_mode: "center"
      ppe_strategy: "head_anchor"
      required_ppe: ["helmet", "vest"]

5. 常見問題與異常排除指南 (Troubleshooting)

  • 外部狀態持續為 UNKNOWN：請檢查 Mock MES API 是否已正常啟動、埠號是否被佔用，或 json_path 格式是否與 JSON 鍵值相符。
  • 彎腰作業時偶發未戴安全帽告警：請確認該電子圍籬設定為 ppe_strategy: head_anchor。預設之 direct_negative 模式僅適用於俯視視角。
  • 全螢幕畫布無任何綠框或紅框：請確認模型是否輸出對應之類別名稱，或於 config.yaml 的 ppe_class_mapping 進行類別映射校正。
