# PRD: UMS 廠區化配置與網卡自動偵測機制

## Problem Statement

目前系統在設定檔中需要手動配置多組 UMS 代理伺服器 URL 清單（`ums_base_urls`）。在廠端產線與邊緣設備（如工廠各站點的 Raspberry Pi 5）部署時，維運工程師需要手動查詢該廠區的伺服器 IP 與 URL，容易發生設定錯誤或耗費額外部署時間。

此外，各廠區（如 FAB 1 ~ FAB 8、FAB T1 ~ T6、TS1、LCM 等）的 UMS 代理端點早已標準化於集中式的 UMS API 組態表（`ums-api-config.json`），且各廠區的內網網段（如 10.26.x.x 屬於 FAB 1）具備清晰的對應規則。現有系統缺乏根據裝置網卡 IP 自動判定廠區的初始化能力，且要求使用者在前端手動維護具體 URL，違背了現場「隨插即用、零繁瑣設定」的維運目標。

## Solution

捨棄設定檔中的 `ums_base_urls` 列表設定，改由獨立的 UMS API 組態管理機制統一維護廠區與端點網址對應關係，並提供廠區選取與初始化網卡自動偵測功能：

1. **設定檔架構簡化**：設定檔中移除 `ums_base_urls`，改以簡潔的廠區欄位 `ums_fab`（小寫代碼，如 `"fab1"`, `"oa"`）儲存。
2. **外部組態與雙層載入架構**：以獨立的 UMS API 組態檔統一維護所有廠區的主備端點清單與網段規則。優先讀取同層外部檔案以利現場自訂維護，封裝執行時則自動 fallback 至內建打包版本。
3. **無人值守開箱初始化（網卡 IP 自動偵測）**：若系統啟動時未設定廠區，自動取得裝置所有非 Loopback IPv4 網卡位址，依據組態檔內的網段前綴規則比對所在廠區。比對命中則自動綁定該廠區，若未命中則預設為辦公區（`oa`）。自動判定後立即持久化回設定檔，並自動清理舊有殘留的端點列表。
4. **Web UI 廠區化操作介面**：使用者透過下拉選單直接切換廠區，系統即時連動以唯讀方式呈現該廠區對應的主備服務網址，徹底告別手動編輯長網址與按鈕增刪的複雜操作。

## User Stories

1. 作為現場維運工程師，我希望設備在全新出廠或未設定廠區時，開機即能根據連線的網路自動偵測並設定正確的廠區，以便達到開箱即用、免手動配置 UMS 連線端點。
2. 作為現場維運工程師，我希望在設備網卡符合特定廠區網段（例如 10.26.x.x 屬於 FAB 1）時，系統能自動預設為該廠區，以便自動連線該廠區專屬的內部 UMS 伺服器。
3. 作為現場維運工程師，我希望在設備處於非生產廠區網段（如一般辦公網段、臨時測試區或外網）時，系統能自動 fallback 預設為 OA 區，以便確保基礎連線可用性。
4. 作為現場維運工程師，我希望開機自動偵測到的廠區能立即持久化寫入設定檔，以便後續啟動直接沿用，且打開設定檔即可一目了然設備所屬廠區。
5. 作為現場維運工程師，我希望在現有舊版設定檔包含舊端點清單時，升級後系統能自動偵測廠區並清理殘留欄位，以便維持設定檔整潔與統一。
6. 作為現場維運工程師，我希望在 Web UI 介面上能透過清晰的下拉選單直接選擇廠區（如 OA, FAB 1, FAB 2 ...），以便在更換機台或網路環境時能快速切換。
7. 作為現場維運工程師，我希望在 Web UI 選擇廠區後，下方能即時以唯讀預覽清單顯示該廠區對應的主備端點網址，以便我能確認連線目標是否正確。
8. 作為現場維運工程師，我希望 Web UI 移除手動新增、刪除及輸入 URL 的輸入框，以便避免現場人為打錯網址導致模型無法同步。
9. 作為現場維運工程師，我希望點擊「測試連線」時，系統能直接使用當前所選廠區的主備端點進行測試，並回報各端點的健康狀態，以便快速排查網路連線。
10. 作為系統管理員，我希望當廠區伺服器 IP 或網段異動時，只需更新外部的 UMS API 組態檔而不需要重新編譯程式，以便降低日常維護成本。
11. 作為邊緣系統開發者，我希望即便外部組態檔意外缺失，打包為單一二進位檔案的程式仍能自動 fallback 讀取內建預設組態，以便保證系統高可用性。
12. 作為邊緣系統開發者，我希望 UMS 客戶端與模型同步模組在讀取端點時完全感受不到底層儲存結構的改變，統一由組態管理層透明提供對應廠區的有效 URL 清單。

## Implementation Decisions

### 1. 組態結構與資料模型異動
- 捨棄設定檔中的端點陣列設定，新增單一廠區代碼欄位 `ums_fab`。
- `ums_fab` 在設定檔中標準化儲存為簡短的小寫字串（例如 `"fab1"`, `"fab2"`, `"oa"`）。
- 當舊版設定檔仍殘留舊有端點陣列欄位時，在系統初始化或存檔時自動予以清除，不再寫入該欄位。

### 2. UMS API 集中組態載入架構
- 集中維護一份 UMS API 組態定義，包含各廠區代碼所對應的主備 API 代理端點清單（`"api.<fab>"`），以及廠區網段定義表（`domainDefine`）。
- 載入優先順序：
  1. 優先讀取應用程式當前工作目錄下的外部組態檔案，方便維運人員就地微調。
  2. 若外部檔案不存在（或在打包封裝環境下），則 fallback 載入應用程式內部預先打包的預設組態。

### 3. 網卡 IP 自動偵測與持久化機制
- **觸發條件**：系統啟動時若檢查到設定檔中未設定廠區（未配置 `ums_fab` 或其值為空），立即觸發自動偵測。
- **偵測演算法**：
  1. 列舉本機所有非 Loopback（排除 `127.0.0.1`）、有效且運作中的 IPv4 介面位址。
  2. 將各 IP 位址與組態檔中的 `domainDefine` 網段前綴進行比對（採嚴格網段前綴比對，即以「前綴 + `.`」開頭，防止如 `10.2` 誤判匹配 `10.26`）。
  3. 若多張網卡同時命中，以第一張命中的有效網卡為準，選定該廠區代碼。
  4. 若所有網卡皆未命中任一廠區規則，則自動指派為預設辦公區（`"oa"`）。
- **持久化行為**：判定出廠區後，立即呼叫組態儲存邏輯將 `ums_fab` 寫回設定檔，並移除舊端點欄位，完成無人值守持久化。

### 4. 端點提供者介面行為
- 組態管理器提供對外取得有效端點清單的方法：
  1. 優先檢查環境變數是否覆寫指定端點（支援單一或逗號分隔 URL）。
  2. 根據目前設定的 `ums_fab`（若無則取 `"oa"`），自集中組態中查出對應的 `"api.<fab>"` 端點列表。
  3. 若組態查無該廠區，則 fallback 提供預設的 OA 代理端點清單。

### 5. Web UI 介面與端點互動調整
- **選單動態化**：後端提供 API 或於模板渲染時傳遞所有可用廠區代碼清單，前端以簡潔的廠區下拉選單呈現。
- **端點預覽唯讀化**：使用者切換廠區時，下方以唯讀 Badge/清單區塊即時呈現該廠區對應的主備端點，徹底移除動態增刪按鈕與自訂 URL 文字輸入框。
- **表單提交契約**：表單儲存僅傳遞 `ums_fab` 欄位值（如 `"fab1"`），後端儲存時更新 `ums_fab` 並確保從儲存結構中排除舊端點陣列。
- **連線測試契約**：連線測試介面接受前端所選之廠區代碼，由後端解析其端點並依序檢測連線狀況，回傳各端點成功/失敗細節與模型數量。

### 6. 打包部署規格調整
- 更新 PyInstaller 打包清單，確保 UMS API 組態檔案包含在二進位打包產物之內（`--add-data`），同時更新隨附之設定檔範本。

## Testing Decisions

良好的測試應聚焦於外部行為、輸入輸出契約與各組件邊界狀態，而非耦合內部私有變數或特定的呼叫時序：

1. **網卡比對與自動偵測單元測試**：
   - 模擬不同網卡 IP 清單（如單張 `10.26.15.2`、多張 `10.67.1.10` 與 `192.168.1.1`、多張皆未命中等情況），驗證自動偵測演算法是否準確回傳對應的廠區代碼（如 `"fab1"`、`"fab2"`）以及 fallback `"oa"`。
   - 驗證邊界狀況：空網卡列表、Loopback 網卡過濾、非標準格式前綴。
2. **組態讀取、持久化與清理測試**：
   - 驗證當組態缺少 `ums_fab` 時，初始化能觸發自動偵測並成功將 `ums_fab` 寫入實體檔案。
   - 驗證儲存時能正確清除舊有 `ums_base_urls`，且不會破壞其他無關的系統參數。
   - 驗證 `get_ums_base_urls()` 在不同 `ums_fab` 下能正確自組態映射出預期的 URL 清單。
3. **Web UI API 整合測試**：
   - 驗證儲存 API 接收 `ums_fab` 後，設定檔內容與回傳狀態正確。
   - 驗證連線測試 API 在給定不同廠區代碼時，能正確使用該廠區的端點進行連線測試並回傳標準格式結果。
4. **既有測試參考**：
   - 參考現有 `test_config_manager.py`、`test_web_ui_config_save.py` 與 `test_web_ui_ums_endpoints.py` 之 Mock 與檔案操作慣例進行擴充。

## Out of Scope

- 在 Web UI 上動態新增、編輯或刪除 `ums-api-config.json` 的廠區內容或網段規則（此設定檔定位為機台出廠與系統維運層級檔案，應透過檔案直接維護）。
- 跨廠區即時自動漂移切換（設備運作期間若實體更換網路插孔，不進行背景動態監聽漂移，僅在重啟初始化或使用者於 UI 切換時生效）。
- 支援非 IPv4 的純 IPv6 網段自動比對。

## Further Notes

- 各廠區 API Proxy 的 URL 格式統一為 `http://<ip>/umsapiproxy/fab4ums`，其主備機制依賴 `FailoverUmsClient` 自動容錯切換。
- 專案程式碼與文件統一遵循本 PRD 定義之專有名詞與欄位名稱（`ums_fab`、`domainDefine`、`api.<fab>`）。
